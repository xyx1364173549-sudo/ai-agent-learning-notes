LCEL 管道式组合

任务 1.2 · 学习笔记 · 2026-08-21 · 前置：LangChain 三大核心抽象

一句话总纲：LCEL 用 |（管道符）把组件串成一条链，一次 invoke 跑完整条链，替代"手动三步走"。

一、核心对比：手动流水线 vs 自动传送带

普通写法（手动，3 步）
prompt = template.format_messages(...)
msg = llm.invoke(prompt)
answer = msg.content

每次手动做 3 步，中间变量手动传

LCEL（自动，1 步）
chain = template | llm | StrOutputParser()
answer = chain.invoke({...})

先组装成链，以后一次跑完

三个新零件

新东西是什么类比
| 管道符串成链，输出自动接输入接水管 / 传送带
StrOutputParser()AIMessage 自动转字符串自动帮你 .content
chain串好的链，可 invoke装好的流水线

二、复用角度（最能说明问题）

同一个模板问 3 个问题：

# 普通写法：9 行，每次重复 3 步
prompt1 = template.format_messages(question="什么是递归？")
msg1 = llm.invoke(prompt1); a1 = msg1.content
prompt2 = template.format_messages(question="什么是闭包？")
msg2 = llm.invoke(prompt2); a2 = msg2.content
prompt3 = template.format_messages(question="什么是装饰器？")
msg3 = llm.invoke(prompt3); a3 = msg3.content

# LCEL：4 行，组装 1 次 + 3 行调用
chain = template | llm | StrOutputParser()
a1 = chain.invoke({"question": "什么是递归？"})
a2 = chain.invoke({"question": "什么是闭包？"})
a3 = chain.invoke({"question": "什么是装饰器？"})
💡 LCEL 把"重复的流程"打包成一个可复用的 chain 对象，像传送带装一次反复用

三、完整代码

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatOpenAI(model="deepseek-v4-flash", api_key=API_KEY,
                 base_url="https://api.deepseek.com")

template = ChatPromptTemplate.from_messages([
    ("system", "你是一个{role}，回答风格要{style}"),
    ("user", "{question}"),
])

# LCEL：用 | 串成链（模板 → 模型 → 解析）
chain = template | llm | StrOutputParser()

reply = chain.invoke({
    "role": "编程老师",
    "style": "通俗易懂，多用类比",
    "question": "什么是递归？",
})
print(reply)   # 直接是字符串，不用 .content

四、难点澄清

1. `|` 到底做了什么？

"自动传参"的语法糖：上一个零件的输出，自动变成下一个零件的输入。

2. StrOutputParser 省掉了什么？

省掉 reply.content 这一步，链最后接上它，invoke 直接返回字符串。

3. 为什么 invoke 传字典？

链的第一个零件是 PromptTemplate，需要字典来填空。

4. LCEL 和普通写法的本质区别？

普通写法 = 手动流水线（每次自己递数据）；LCEL = 自动传送带（装好一次，自动流）。

5. LCEL 的三个价值

复用（组装一次反复用）、可读（一眼看数据流）、可组合（链还能拼接，LangGraph 基础）。
