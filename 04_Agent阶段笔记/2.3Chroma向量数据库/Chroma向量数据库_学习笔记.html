2.3 Chroma 向量数据库

阶段二 · RAG 落地 · 建索引 + 语义检索
一句话总结：向量数据库 = 存向量 + 按语义检索的仓库。它本身不智能，检索准不准完全取决于喂给它的 embedding 模型好不好。

核心流程

add（文本 → 自动向量化 → 存） →  query（问题 → 向量化 → 找距离最近的几条）

类比：图书馆语义检索——问"怎么解方程"，不搜"求根公式"三个字，而是按"意思"找到最相关的那张卡片。

知识点

① 向量数据库 vs 传统数据库概念

传统（MySQL）向量（Chroma）
查询方式精确匹配语义相似
字面不同语义相同搜不到能命中

② Chroma 四个核心操作API

client = chromadb.Client()               # ① 客户端
collection = client.create_collection(...) # ② 建库（英文名）
collection.add(documents=..., ids=...)     # ③ 存（自动向量化）
collection.query(query_texts=..., n_results=2)  # ④ 查

③ 英文模型中文翻车（实测）⭐最关键的发现

问「怎么解一元二次方程」，返回顺序：

排名结果距离
第 1 名勾股定理（错）0.641
第 2 名二次方程求根公式（对）0.799

核心认知：向量库只是仓库，检索不准是 embedding 模型的锅。默认英文模型分不清中文概念，论文要换 BGE 中文模型。

④ ids 是编号易混淆

ids 和 documents 是两个列表，靠下标位置一一对应。

类比：学生名单两列——"学号"（ids）+ "姓名"（documents）。ids 就是学号，不是"拆分方式"。

⑤ L2 距离 vs 余弦相似度度量

度量规则在哪见过
L2 欧氏距离（Chroma 默认）越小越相似2.3 的 0.641
余弦相似度越大越相似2.1 的 0.75

L2 = 勾股定理推广到多维，应用岗了解"越小越相似"即可，不用系统学。

核心代码

collection.add(
    documents=["二次方程的求根公式是...", "Python 是一种...", "勾股定理：..."],
    ids=["math1", "python1", "math2"],
)
result = collection.query(query_texts=["怎么解一元二次方程"], n_results=2)

踩坑

#62 collection 名用中文 → InvalidArgumentError（名字只能英文/数字，documents 内容可中文）
#63 默认模型从 AWS S3 下载（79MB）极慢 → 手动下载 onnx.tar.gz 放到缓存目录绕过
