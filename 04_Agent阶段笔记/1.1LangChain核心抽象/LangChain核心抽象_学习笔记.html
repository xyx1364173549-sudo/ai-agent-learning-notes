一、三大核心抽象

ChatModel万能插座

统一 LLM 接口，换模型只改 model / base_url。

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="deepseek-v4-flash",           # 用什么模型
    api_key=API_KEY,                     # 身份凭证
    base_url="https://api.deepseek.com", # 模型地址
)

reply = llm.invoke("用一句话介绍你自己")
print(reply.content)   # AIMessage 对象，用 .content 取正文
💡 invoke = 榨汁机：放原料 → 运转 → 出果汁（传参 + 执行 + 返回 三合一）

PromptTemplate填空题

把"固定文字"和"变量"分开，变量挖成空位 {变量}。

from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_messages([
    ("system", "你是一个{role}，回答风格要{style}"),
    ("user", "{question}"),
])

prompt = template.format_messages(
    role="编程老师", style="通俗易懂", question="什么是递归？",
)
💡 from_messages 的元组 (角色, 内容) = 手写的 {"role":..., "content":...}；format_messages 返回的 messages 列表，正好喂给 invoke

Tool文件袋（三自动）

@tool 把普通函数变成工具，自动生成说明书。

from langchain_core.tools import tool

@tool
def get_weather_tool(city: str) -> str:
    """查询指定城市的天气"""
    return f"{city} 今天晴天，20°C"
函数里的信息自动变成对应手写
函数名 get_weather_toolname"name"
docstring 查询...天气description"description"
类型注解 city: strparametersJSON Schema
⚠️ docstring 不是注释！它是 Python 存到 函数.__doc__ 的元数据。@tool 读的是 __doc__，不是"AI 读注释"

二、完整闭环（两次调用）

1
PromptTemplate 拼出带角色的 messages 列表
▼
2
ChatModel（第 1 次） AI 思考 → 返回 tool_calls（决定调工具，content 为空）
▼
3
Tool 执行 get_weather_tool.invoke → "晴天 20°C"
▼
4
ChatModel（第 2 次） 收到工具结果 → 组织成自然语言
llm_with_tools = llm.bind_tools([get_weather_tool])   # 装工具箱，返回新副本

human_msg = HumanMessage(content="北京天气怎么样")
msg = llm_with_tools.invoke([human_msg])               # 第 1 次：下令

tool_messages = []
for tool_call in msg.tool_calls:
    result = get_weather_tool.invoke(tool_call["args"])
    tool_messages.append(ToolMessage(content=result, tool_call_id=tool_call["id"]))

final = llm_with_tools.invoke([human_msg, msg, *tool_messages])  # 第 2 次：组织语言
print(final.content)

三、难点澄清（理解这些才算真懂）

1. docstring 为什么能被 @tool 读到？

docstring 是 Python 存到 函数.__doc__ 的元数据，# 注释才被忽略。AI 看不到源代码，只看到 HTTP 请求里的 JSON。

2. invoke 是什么意思？

传参 + 执行 + 返回，三合一。是 LangChain 统一的"运行开关"。

3. @tool 之后函数变了吗？

变了，变成 StructuredTool 对象：.name / .description / .func 可用，.__name__ 报错。

4. bind_tools 是什么意思？

创建"带工具箱的模型副本"，llm 不变。

5. 为什么第二次还用 llm_with_tools？

保留 AI"继续调工具"的能力。content 空值 = AI 在下令（第一次只下令不开口）。

6. 数据是怎么流动的？（template 和 prompt 怎么到 llm）

template 和 prompt 是"一条流水线上的两站"：template(带空位) → format_messages 填空 → prompt(填好的 messages) → invoke(prompt) 传参 → llm。连接靠"函数传参"，不是 from_messages（它只负责"造模板"）。

7. 消息类型（HumanMessage / ToolMessage）

LangChain 把四种 role 做成了类：SystemMessage(system) / HumanMessage(user) / AIMessage(assistant) / ToolMessage(tool)。ToolMessage 多一个 tool_call_id 字段，用于"对号入座"。
