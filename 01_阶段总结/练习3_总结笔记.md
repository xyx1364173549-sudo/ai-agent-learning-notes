## 一、你问过的问题 → 答案速查

### Q1：`json body` 参数是什么？我只记得 url、params、timeout

**答：** `json=` 是 POST 请求的"请求体"参数，用来把要提交的数据发给服务器。

```python
requests.post(url, json={"prompt": "AI", "model": "test"}, headers=headers, timeout=10)
#                  ↑ 这个 json= 就是请求体
```

`requests` 会自动帮你：
1. 把字典转成 JSON 字符串
2. 设置 Content-Type 头
3. 塞进请求体发送

### Q2：3.1 的参数 q=query、format=json、no_html=1 是干什么的？

**答：** 这些参数是**这个 API 自己定义的接口规范**，不是随便写的：

| 参数 | 含义 | 类比 |
|------|------|------|
| `q=query` | 搜索什么内容 | 告诉厨师"我要点什么菜" |
| `format=json` | 响应用 JSON 格式 | 告诉服务员"打包带走" |
| `no_html=1` | 结果不要 HTML 标签 | 告诉服务员"不要配菜，只要主菜" |

**核心认知：** 你传什么参数、能拿到什么，取决于 API 文档（"菜单"）怎么规定。**开发者的日常工作就是：先查文档，再写代码。**

### Q3：为什么传 "python" 能拿到数据？传其他字符串不行吗？

**答：** 传其他字符串**完全没问题**！`search_duckduckgo("AI")`、`search_duckduckgo("香蕉")` 都能成功。

区别只在于**结果内容**：
- 传 "python" → 服务器数据库里有 → 返回详细资料
- 传 "asdfghjkl" → 服务器查不到 → 返回空结果

**结论：** 参数决定"服务器查什么"，返回什么取决于**服务器数据库里有没有**。

### Q4：获取的是什么数据？

**答：** DuckDuckGo 的"即时答案"（Instant Answer）——来自 Wikipedia 等来源的结构化数据。比如传 "python" 会返回编程语言 Python 的简介、相关链接等。

### Q5：3.2 的 body 传的是什么？传 "AI" 能得到什么？

**答：** body 就是**你发给服务器的话**。我们用本地服务器实测过：

```
客户端发送:  {"prompt": "AI", "model": "test"}
服务器回显:  {'echo': {'prompt': 'AI', 'model': 'test'}, ...}
```

**在真实 LLM API 里**，这个 body 就是"发给大模型的指令"，`prompt` 字段就是你问 AI 的问题，服务器会返回模型的回答。

### Q6：`if __name__ == "__main__":` 是什么意思？

**答：** Python 自动给每个文件设置 `__name__` 变量：
- **直接运行**这个文件 → `__name__ = "__main__"` → 执行 if 块里的测试代码
- **被 import** → `__name__ = 文件名` → 跳过测试代码，只加载函数

```python
def search_duckduckgo(query):
    ...          # ← 函数定义（给别人用的）

if __name__ == "__main__":
    result = search_duckduckgo("python")   # ← 测试代码（自己调试用的）
    print(result)
```

**作用：** 让同一个文件既能"直接运行测功能"，又能"被导入复用函数"，互不干扰。这是模块化的基础。

### Q7：`result = search_duckduckgo("python")` 传参是干什么的？

**答：** 函数是"加工厂"，参数是"原材料"：
- `def search_duckduckgo(query)` → `query` 是占位符，函数不知道要搜什么
- `search_duckduckgo("python")` → 把具体内容放进去
- 不传参 → 报错 `missing 1 required positional argument: 'query'`
- `result =` → 接住函数返回的结果，否则结果就丢了

### Q8：为什么 import 不了我的练习文件？

**答：** 因为文件名是 `练习 3.1：GET 请求（带参数）.py`——**含中文、空格、冒号、括号，不是合法的 Python 模块名**。

**规范：** 文件名用英文小写 + 下划线，如 `weather_tool.py`、`my_tools.py`。

## 二、核心知识点：GET vs POST

| | GET（3.1） | POST（3.2） |
|---|---|---|
| 用途 | 获取数据 | 提交数据 |
| 参数位置 | URL 上 `?q=python` | 请求体里 |
| requests 写法 | `requests.get(url, params=...)` | `requests.post(url, json=...)` |
| 典型场景 | 查天气、搜索 | 调用 LLM API |

**记忆口诀：** GET 是"问"，POST 是"给"。

## 三、核心知识点：异常处理（3.3）

### 为什么必须加 try-except？

网络请求一定会失败：断网、超时、服务器 503、返回格式不对……**不处理就会崩溃**。

### 标准写法（背下来）：

```python
from requests.exceptions import Timeout, ConnectionError, HTTPError

def safe_get(url: str) -> dict | None:
    try:
        resp = requests.get(url, timeout=10)
        resp.raise_for_status()      # ⭐ 4xx/5xx 时主动抛异常
        return resp.json()
    except Timeout:
        print("[超时] 请求超时")
    except ConnectionError:
        print("[网络] 无法连接服务器")
    except HTTPError as e:
        print(f"[HTTP] 状态码: {e.response.status_code}")
    except ValueError:
        print("[解析] 响应不是合法 JSON")
    return None
```

### 四个异常的含义

| 异常 | 触发场景 |
|------|---------|
| `Timeout` | 服务器超时没响应 |
| `ConnectionError` | 网络断、连不上服务器 |
| `HTTPError` | 服务器返回 4xx/5xx 错误码 |
| `ValueError` | 响应不是合法 JSON |

### 我的实测结果（全部通过 ✅）

```
/ok        → {'status': 'ok', 'data': [1, 2, 3]}  正常
/notfound  → [HTTP] 状态码: 404                    HTTP 错误
/error500  → [HTTP] 状态码: 500                    HTTP 错误
/html      → [解析] 响应不是合法 JSON              解析错误
/slow      → [超时] 请求超时                       超时
```

## 四、一次性把"发请求"的全流程记住

```
1. 导入 requests
2. 定义 url
3. 构造参数（GET 用 params / POST 用 json）
4. 发送请求（带 timeout）
5. raise_for_status() 检查状态码
6. resp.json() 解析
7. 分类型捕获异常
8. 返回结果
```

**这就是调用任何 LLM API（OpenAI、通义、文心）的完整姿势。**
