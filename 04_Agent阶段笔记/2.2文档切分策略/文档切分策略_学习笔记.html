阶段二 · 任务 2.2

文档切分策略

固定长度 + 重叠窗口 —— RAG 的第二环

一、一句话总结

把长文档切成小块（chunk），每块单独向量化、单独检索，让检索精准命中"讲求根公式的那一小段"，而不是返回"整本书相关"。
核心技巧：重叠窗口 —— 相邻块留部分重叠，边界附近的关键信息不因一刀切而丢失。

二、为什么要切分？（两个原因）

原因说明
向量化有长度限制embedding 模型一次只能处理几百到几千字，超长文本塞不进去
检索颗粒度太粗问"求根公式是什么"，返回"整本书的向量"只能定位到书，定位不到段落

类比：把厚书拆成"卡片"，每张一个知识点。查资料直接抽"求根公式"那张卡，不用抱整本书。

三、三种切分策略

策略怎么做优点缺点
固定长度按固定字符数切（每 50 字一块）简单可能在句子中间切断
按段落/标题按文档天然结构切保留语义完整依赖文档格式规整
语义切分 + 重叠窗口按语义找切分点，相邻块留重叠最准、不丢信息最复杂

四、重叠窗口（核心技巧）

痛点：一刀切会把词切成两半

固定长度切分，可能正好把"二次方程"切成"二次方"+"程"——两个 chunk 都不完整，谁也匹配不上。

解法：让相邻块有部分重叠

块0（末尾）
…它允许模型并行地捕捉序列中的核心是自注意力机制
块1（开头，与块0 重叠 10 字）
的核心是自注意力机制，它允许模型并行地捕捉序列中…

边界附近的关键信息（橙色部分）在两个块里都完整存在 → 检索时不会漏。

实现的关键一行：步长

步长 = chunk_size - overlap
start += chunk_size（无重叠）  →  start += chunk_size - overlap（重叠）

代价是存储冗余（重叠部分存两遍），换来检索不丢信息 —— RAG 里很划算。

五、边界条件（off-by-one 陷阱）

写法结果
while start < len(text)✅ 正确：start 还没到末尾就继续
while start <= len(text)❌ 错误：start 顶到末尾还切，多出一块空字符串
反例验证：text 长 100、步长 50 → <= 切出 [50, 50, 0]（多空块），< 正确得 [50, 50]。

六、代码段

def chunk_text(text, chunk_size, overlap):
    chunks = []
    start = 0
    while start < len(text):                # 边界：start 还没到末尾
        chunks.append(text[start:start+chunk_size])
        start += (chunk_size - overlap)     # 关键：步长 = 块长 - 重叠
    return chunks

# 每块 50 字，重叠 10 字
chunks = chunk_text(text, chunk_size=50, overlap=10)

七、踩坑记录

#61 · 切分循环用了 <= 而不是 <
当 text 长度被步长整除时，start == len(text) 会切片出空字符串多一块（反例：100 字/步长 50 → [50,50,0]，应为 [50,50]）。
规律：边界条件用"还没越界"的 <，不是"允许刚好越界"的 <=。
