2.6 多 Agent 协作

LangGraph 编排 导师 / 出题 / 评估 / 规划 四 Agent 分工 → 论文第 5 章"动态任务规划"前置
多 Agent 协作 = 用 LangGraph 把一个"全能 Agent"拆成四个各司其职的 Agent（导师讲 → 出题考 → 评估分 → 规划下一步），节点之间靠结构化的 State 字段传"接力棒"，条件边根据掌握度决定"重讲 / 推进 / 收工"，再用轮次计数器保证循环必然终止。

〇、为什么不能只用一个全能 Agent？

痛点单全能 Agent四 Agent 分工
Prompt 冲突讲知识/出题/批改/规划四套人设塞一个提示词，互相打架每人一套专属人设，互不干扰
状态混乱讲完课顺手出题，出题人设污染讲课语气各管一段，交接清晰
难扩展想加个"心理疏导 Agent"要改全图加个节点 + 一条边就行

类比：医院科室——不会让一个医生既看门诊又做检验又发药。每个环节专人做，质量才稳。

四 Agent 流水线

START → tutor(讲解) → quiz(出题) → eval(批改) ─┬─ mastery≥0.7 ──→ plan(规划) ─┐
                                               ├─ 没学会,轮次<3 → 回 tutor 重讲 │
                                               └─ 3轮没学会 / 总轮≥5 → 收工 END ←┘
Agent职责产出（写入 State）
tutor 导师讲解当前知识点lecture
quiz 出题按知识点出练习题question
eval 评估批改答案、打掌握度（最难）feedback + mastery + round
plan 规划决定下一知识点next_topic（顺手更新 topic）

一、对应知识点

1.1 从 1.5 到 2.6：三处架构升级

维度1.5 单 Agent2.6 多 Agent
State只有 messages（对话流水账）一堆具名字段（接力棒）
节点llm_with_tools（带工具）带人设的普通 LLM
条件边判断"有没有 tool_calls"判断"学没学会"
循环call_model ↔ tool_node（技术循环）eval ↔ plan/retry（业务循环）

关键认知：多 Agent 之间传的不是"聊天记录"，是结构化的接力棒——题目、答案、掌握度、下一知识点各有归属。

1.2 State：接力棒字典（谁写谁读要记牢）

class AgentState(TypedDict, total=False):
    topic: str           # 当前知识点（plan 换新）
    lecture: str         # tutor 写
    question: str        # quiz 写
    student_answer: str  # 外部传入
    feedback: str        # eval 写
    mastery: float       # eval 写（条件边的依据）
    next_topic: str      # plan 写
    round: int           # eval 写（防死循环出口）

LangGraph 合并机制：节点只 return 自己改写的字段（一个 dict），LangGraph 自动合并回总 State，没返回的字段原样保留。

1.3 节点模式：一个节点 = 人设 + 一次 invoke + return dict

def tutor_node(state: AgentState) -> dict:
    resp = llm.invoke([
        SystemMessage(content=TUTOR_PROMPT.format(topic=state["topic"])),
        HumanMessage(content="请开始讲解"),
    ])
    return {"lecture": resp.content}   # 纯文本,不 json.loads!
节点prompt 要求resp.content 里是处理方式
tutor3 句话讲解普通文本直接用
quiz1 道题普通文本直接用
evalJSONJSON 文本json.loads 解析（三层兜底）
plan只输出知识点名普通文本strip() 后用

信封 vs 信纸：resp.content 永远是 str

HTTP 响应是 JSON（含 usage/id/choices），那是信封；LangChain 拆完信，resp.content 是信纸——类型恒为 str。模型输出"人话还是 JSON 文本"，取决于 prompt 怎么要求，与返回值类型无关。

判据（可复用工程规矩）：输出格式的契约写在 prompt 里，解析方式跟着契约走。prompt 没要求 JSON 就绝不 json.loads；要求了才解析。

1.4 条件边：四段式判定 + 防死循环

两条铁律（本节的灵魂）
铁律一：状态修改只发生在节点里，条件边只负责指路（round+1 在 eval_node）。
铁律二：循环计数器必须放在所有路径的必经节点上——plan→quiz 回边绕过 tutor，round 放 tutor 会让"一直答对"死循环；quiz/eval 是汇合点，放 eval 语义最贴切（考完一次 = 学了一轮）。

死循环推演（round 放 tutor 的后果）

1. tutor 进入      round = 0+1 = 1
2. quiz → eval     mastery=0.9 → should_continue 判:≥0.7 → plan
3. plan → quiz     ← 回边不经过 tutor! round 再没机会 +1
4. eval → plan → quiz → eval → ... 无限循环,round 永远 = 1,硬上限失效

正确版本

def should_continue(state: AgentState) -> str:
    r = state.get("round", 0)
    m = state.get("mastery", 0.0)
    if r >= 5:                  # ① 总轮次硬上限(兜 plan 回边那条路)
        return "end"
    if m >= 0.7:                # ② 学会了 → 去规划
        return "plan"
    if r < 3:                   # ③ 没学会还有机会 → 回导师重讲
        return "retry"
    return "end"                # ④ 学了 3 轮还不会 → 收工

round + 1 写在 eval_node 的 return 里："round": state.get("round", 0) + 1

终止性（论文/答辩素材）

路径经过 tutor?出口
eval → retry → tutor → quiz → eval✅round 到 3 收工
eval → plan → quiz → eval❌ 绕过round 到 5 收工（硬上限）

工业做法：两个计数器——round（总轮次防死循环）+ retry_count（当前知识点重讲次数，换知识点清零）。一个 round 顶两个用是教学简化，第 5 章可展开。

1.5 eval_node：三层兜底 + 钳制（本节最难的函数）

def eval_node(state: AgentState) -> dict:
    resp = llm.invoke([SystemMessage(content=EVAL_PROMPT.format(
            topic=state["topic"],
            question=state.get("question", ""),
            answer=state.get("student_answer", ""),
        )), HumanMessage(content="请批改这份答案")])
    text = resp.content.strip().replace("```json", "").replace("```", "")   # ① 剥壳

    try:                              # ② 正常路径:json.loads
        data = json.loads(text)
        mastery = float(data["mastery"])
        feedback = data.get("feedback", "")
    except Exception:                 # ③ 备用:正则抠第一个数字
        m = re.search(r"\d\.?\d*", text)
        mastery = float(m.group()) if m else 0.0
        feedback = text[:50]

    mastery = max(0.0, min(mastery, 1.0))   # ④ 钳制:锁进 0~1
    return {"feedback": feedback, "mastery": mastery,
            "round": state.get("round", 0) + 1}

① 正则 \d\.?\d*

\d 一个数字；\. 真正的点（. 在正则里是"任意字符"要转义）；? 可有可无；\d* 零或多个数字。匹配 8/0.8/0.85。re.search 找到返回匹配对象，.group() 取字符串；找不到返回 None。

② try/except 接异常，不是 if 接

json.loads 解析失败是 raise（打断程序），不是返回空值——所以不能用 if/elif/else 接它。类比：钥匙卡住换备用钥匙（正则），还不行就撬锁（默认 0.0）。

③ 钳制 —— prompt 是请求，不是保证

模型实际给的不钳制钳制后说明
{"mastery": 0.8}0.80.8正常值，没被误伤
{"mastery": 85}（百分制）85.01.085 ≥ 0.7 会误判"学会"
"我给 85 分"85.01.0同上
"第 3 题答案正确"3.01.0正则抠到的是题号
{"mastery": -0.2}-0.20.0负数永远走 retry 重讲到天荒地老
{"mastery": 1.5}1.51.0超范围
类比：prompt 写"0~1"像前台提示牌，max/min 像门口安检机——提示牌防君子，安检机防意外，真实系统两层都要。诚实补充：钳制是"保命不保准"（85→1.0 而非 0.85），更严谨做法是 if 1 < mastery <= 100: mastery /= 100，留给 2.7。

1.6 搭图五步

graph = StateGraph(AgentState)
graph.add_node("tutor", tutor_node)          # ① 注册 4 个节点(漏一个 → 编译报
graph.add_node("quiz", quiz_node)            #    "Found edge starting at unknown node")
graph.add_node("plan", plan_node)
graph.add_node("eval", eval_node)
graph.add_edge(START, "tutor")               # ② 固定边
graph.add_edge("tutor", "quiz")
graph.add_edge("quiz", "eval")
graph.add_conditional_edges("eval", should_continue,   # ③ 条件边 + 映射表
    {"plan": "plan", "retry": "tutor", "end": END})
graph.add_edge("plan", "quiz")               # ④ 循环回边(绕过 tutor!)
app = graph.compile()                        # ⑤ 编译

注意：add_node 注册 ≠ add_edge 连边，两个都不能漏。LangGraph 只在 compile() 时检查"边指向的节点是否存在"。

1.7 留给 2.7 的设计缺口（本章最有价值的产出）

缺口现象2.7 的正解
规划 Agent 没有"结束"信号学完最后一个知识点，plan 输出"无"，图不停止，白烧一轮靠 round≥5 兜底规划输出结构化决策：推进 / 巩固 / 重学 / 结束，结束交条件边直接 END
mastery 在 plan 里区分度有限should_continue 已用 0.7 分流，进 plan 的 mastery 恒 ≥0.72.7 里 mastery 才真正决定"推进/巩固/跳级/回退"路径

二、测试与验收

三场景走查（真实运行输出）

场景输入实际路径结果说明
A 随机出题+固定答案答案写死但题随机 → 错配retry×…→end掌握度 0.0演示数据缺陷，不是 bug
B 答错"不会"retry×2 → end0.0，round=3 正常停防死循环出口生效 ✅
C 固定题+正确答案预置 question，答对plan ×…→ round≥5 停1.0，推进到下一知识点演示 plan 分支要固定题目

演示 plan 分支的做法：quiz_node 加一行 if state.get("question"): return {}——外部已有题目就不生成。

边界测试 13/13（方法：桩函数替掉 LLM）

测试思想（面试可讲）：把 tutor/quiz/plan 换成返回固定值的桩函数（stub），只测"图怎么走"、不测"模型说啥"——不烧 API、结果可复现。这就是单元测试里"隔离外部依赖"的思想。

场景验证点结果
一直答对（0.95）round 到 5 停（不死循环）+ 进 plan + next_topic✅
一直答错（0.2）round 到 3 收工 + plan 0 次 + tutor 3 次✅
先错两次再对最终 0.9 + plan 2 次✅
```json 包裹剥壳解析出 0.85✅
纯文本"大概 0.6 分"正则抠出 0.6✅
无数字文本兜底给 0.0（不崩）✅
百分制 80钳制到 1.0✅
round 自增每批改一次 +1✅
排错插曲：场景 3 一度判 FAIL——最后发现是测试脚本的期望值算错了（plan 应被调用 2 次而非 3 次），代码本身是对的。期望值错 ≠ 代码错，先走查再改代码。

四、论文定位（第 5 章动态任务规划的前置）

  • 流水线拆分：把"教学"拆成导师/出题/评估/规划四个工位——第 5 章让规划 Agent 从"输出一个知识点名"升级为"输出完整学习路径策略"。
  • 接力棒 State：多 Agent 传结构化字段而非聊天流水账——多 Agent 系统设计第一原则，可写进论文方法部分。
  • 终止性证明：枚举两条回边 + 各自出口，答辩被问"会不会死循环"直接背这段。
  • 双计数器：round（防死循环）+ retry_count（当前知识点重试）的取舍，第 5 章可展开。
  • 规划决策结构化：plan 输出"无"不结束的缺口 = 第 5 章要解决的第一个真问题。

五、代码段（关键骨架）

def tutor_node(state):
    resp = llm.invoke([SystemMessage(content=TUTOR_PROMPT.format(topic=state["topic"])),
                       HumanMessage(content="请开始讲解")])
    return {"lecture": resp.content}          # 纯文本,不解析

def quiz_node(state):
    if state.get("question"):
        return {}                             # 外部已指定题目 → 沿用
    resp = llm.invoke([SystemMessage(content=QUIZ_PROMPT.format(topic=state["topic"])),
                       HumanMessage(content="根据知识点出题")])
    return {"question": resp.content}

def eval_node(state):
    resp = llm.invoke([SystemMessage(content=EVAL_PROMPT.format(
        topic=state["topic"], question=state.get("question",""),
        answer=state.get("student_answer",""))), HumanMessage(content="请批改这份答案")])
    text = resp.content.strip().replace("```json","").replace("```","")
    try:
        data = json.loads(text)
        mastery = float(data["mastery"]); feedback = data.get("feedback","")
    except Exception:
        m = re.search(r"\d\.?\d*", text)
        mastery = float(m.group()) if m else 0.0
        feedback = text[:50]
    mastery = max(0.0, min(mastery, 1.0))
    return {"feedback": feedback, "mastery": mastery,
            "round": state.get("round", 0) + 1}   # 计数放必经节点

def plan_node(state):
    resp = llm.invoke([SystemMessage(content=PLAN_PROMPT.format(
        topic=state["topic"], mastery=state.get("mastery", 0.0))),
        HumanMessage(content="请决定下一个知识点")])
    nxt = resp.content.strip()
    return {"next_topic": nxt, "topic": nxt}   # topic 也要换!否则出题还考旧的

def should_continue(state):
    r = state.get("round", 0); m = state.get("mastery", 0.0)
    if r >= 5:  return "end"      # ① 硬上限兜底(plan 回边那条路)
    if m >= 0.7: return "plan"    # ② 学会了
    if r < 3:   return "retry"    # ③ 没学会,再试
    return "end"                  # ④ 3 轮还不会,收工
