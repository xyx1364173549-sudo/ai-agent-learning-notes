# 2.3 Chroma 向量数据库

## 一、总结

> **向量数据库 = 存向量 + 按语义检索的仓库。它本身不智能，检索准不准完全取决于喂给它的 embedding 模型好不好。**

这一步把 2.1（文字→向量）和 2.2（切分文档）真正落地：把"一块块文本"变成向量存进 Chroma，问问题时返回"语义最接近"的几块。

---

## 二、对应知识点

### 知识点 1：向量数据库 vs 传统数据库

| | 传统数据库（MySQL） | 向量数据库（Chroma） |
|---|---|---|
| 查询方式 | 精确匹配（`WHERE 标题='求根公式'`） | 语义相似（问"怎么解方程"能命中"求根公式"） |
| 字面不同但语义相同 | ❌ 搜不到 | ✅ 能命中 |
| 底层 | 索引 + SQL | 向量距离计算 |

### 知识点 2：Chroma 四个核心操作

```python
client = chromadb.Client()                      # ① 客户端（内存版，重启丢）
collection = client.create_collection("name")   # ② 建知识库（名字只能英文数字）
collection.add(documents=[...], ids=[...])      # ③ 添加（自动向量化 + 存）
collection.query(query_texts=[...], n_results=2) # ④ 检索（返回最相似的几条）
```

- **Client**：内存版，重启就丢；真实项目用 `PersistentClient` 存磁盘。
- **add**：自动把文本变成向量（不用自己调 embedding）。
- **query**：把问题也向量化，返回"距离最近"的几条。

### 知识点 3：语义检索的威力

问「怎么解一元二次方程」，**没提"求根公式"三个字**，但能命中"二次方程求根公式"那条——这就是向量数据库和普通搜索的本质区别：按"意思"找，不是按"字"找。

### 知识点 4：英文模型中文翻车（实测案例 ⭐）

默认模型 `all-MiniLM-L6-v2` 是英文训练的，中文语义理解差。实测检索结果：

| 排名 | 结果 | 距离 |
|---|---|---|
| 第 1 名 | ❌ 勾股定理 | 0.641 |
| 第 2 名 | ✅ 二次方程求根公式 | 0.799 |

问"怎么解一元二次方程"，**勾股定理排在了二次方程前面**——英文模型分不清中文的数学概念。

**核心认知**：向量数据库只是"仓库"，检索准不准取决于 embedding 模型。论文必须换中文模型（BGE）。

### 知识点 5：`ids` 是编号，不是拆分

`ids=["math1", ...]` 和 `documents=[...]` 是两个列表，**靠下标位置一一对应**。

**类比**：学生名单的两列——"学号"（ids）和"姓名"（documents）。ids 就是学号。

### 知识点 6：L2 距离 vs 余弦相似度

| 度量 | 规则 | 你在哪见过 |
|---|---|---|
| **L2 欧氏距离**（Chroma 默认） | 值**越小**越相似 | 2.3 的 `distances: 0.641` |
| **余弦相似度** | 值**越大**（接近1）越相似 | 2.1 手算的 0.75 |

- L2 = 勾股定理推广到多维（`√(Σ(aᵢ-bᵢ)²)`），初中就会，**不用系统学**。
- 文本 RAG 通常更推荐**余弦**（只看方向，不受向量长度干扰），论文调检索效果时会用到。

## 三、对应代码段

```python
"""2.3 Chroma 向量数据库：建索引 + 语义检索"""
import chromadb

client = chromadb.Client()                      # 内存版客户端
collection = client.create_collection("study_materials")   # 名字必须英文/数字

collection.add(
    documents=[
        "二次方程的求根公式是 x = (-b ± √(b²-4ac)) / 2a",
        "Python 是一种解释型编程语言",
        "勾股定理：直角三角形两直角边平方和等于斜边平方",
    ],
    ids=["math1", "python1", "math2"],
)

result = collection.query(
    query_texts=["怎么解一元二次方程"],   # 没提"求根公式"，靠语义命中
    n_results=2,
)
print(result)
```

**运行结果**：

```
{'ids': [['math2', 'math1']],
 'documents': [['勾股定理...', '二次方程的求根公式...']],
 'distances': [[0.641, 0.799]]}
```

注意：`math2`（勾股定理）排第 1，距离 0.641 更小；`math1`（二次方程）排第 2。**这是英文模型中文效果差的实证**——换成 BGE 中文模型后，二次方程才会排第 1。
