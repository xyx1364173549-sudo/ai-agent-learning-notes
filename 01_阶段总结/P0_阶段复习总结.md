# 1️⃣ 字符串格式化（f-string）

## 核心概念

f-string 是 Python 3.6+ 的字符串模板，用 `f` 前缀 + `{}` 插值，**是 Agent 开发中最常用的字符串构造方式**（构造 Prompt 模板、格式化输出、写日志）。

## 语法速查

```python
name = "小轩轩"
version = 1.0
tools = ["search", "calc"]

# 基本插值
msg = f"我是 {name}，版本 {version}"        # 我是 小轩轩，版本 1.0

# 表达式（{} 里可以写任何表达式）
f"工具数量: {len(tools)}"                    # 工具数量: 2

# 数字格式化
score = 95.5678
f"得分: {score:.2f}"                         # 得分: 95.57（保留2位小数）
count = 1234567
f"用户数: {count:,}"                          # 用户数: 1,234,567（千分位）

# !r 显示 repr（自动加引号，调试利器）
word = "hello"
f"{word}"                                     # hello
f"{word!r}"                                   # 'hello'（带引号）

# 配合 json.dumps 输出结构化内容
import json
data = {"system": "你是一个助手", "user": "你好"}
json.dumps(data, ensure_ascii=False, indent=2)  # 美化 JSON 输出
```

## 常见错误（练习 1 踩过的坑）⚠️

1. **中英文标点混用**：`f"我是{name},第{day}天"` 输出英文逗号，预期是中文逗号 `，`。**标点要自己手敲，IDE 不帮你转。**
2. **函数封装**：能封成函数就不要写死在脚本里（`build_prompt()` 可以反复调用）。
3. **`!r` 忘记用**：调试打印对象时，`!r` 能显示类型信息。

## 自测清单

- [ ] 能插入变量和表达式到 `{}`
- [ ] 能格式化数字（`.2f`、`:,`）
- [ ] 会用 `!r` 显示 repr
- [ ] 能配合 json.dumps 输出格式化 JSON

# 2️⃣ 字典与列表操作

## 核心概念

字典（dict）和列表（list）是 Agent 处理数据的"血管"：LLM 的 API 响应是字典、消息历史是列表、工具参数是字典。**必须熟练到不用想就能写。**

## 语法速查

```python
# ---------- 字典访问 ----------
response = {"choices": [{"message": {"content": "你好！"}}]}

# 方式1：[] 直接访问（键不存在会 KeyError 崩溃）
response["choices"]                # [{'message': {'content': '你好！'}}]

# 方式2：.get() 安全访问（键不存在返回默认值，不崩溃）
response.get("usage", {})          # {}（没有 usage 键，返回默认空字典）
response.get("choices")            # 正常取值

# 链式访问（层层深入）
response["choices"][0]["message"]["content"]   # 你好！

# ---------- 列表操作 ----------
messages = [{"role": "user", "content": "你好"}]

messages.append({"role": "assistant", "content": "嗨"})   # 追加（列表加元素用 append！）
messages[-1]                        # 最后一个元素
len(messages)                       # 长度

# ---------- 字典合并（配置覆盖）----------
default = {"model": "gpt-3.5", "temperature": 0.7, "max_tokens": 1000}
user_cfg = {"temperature": 0.9}

merged = {**default, **user_cfg}    # 方式1：解包合并（推荐，不修改原字典）
# → {"model": "gpt-3.5", "temperature": 0.9, "max_tokens": 1000}

default.update(user_cfg)            # 方式2：update（会原地修改 default！）
```

## 关键区分 ⚠️（练习 2 踩过的坑）

**列表加元素 vs 字典加键值对是完全不同的：**

```python
# 列表（有序，有位置概念）→ 用 append
my_list = [1, 2, 3]
my_list.append(4)                    # ✅ 正确

# 字典（无序，靠 key 找 value）→ 直接下标赋值
my_dict = {"a": 1}
my_dict["b"] = 2                     # ✅ 正确

# ❌ 错误示范（练习2 的报错）：
# response["choices"][2]["message"] = {...}   # 越界 + 链式赋值，直接 SyntaxError
```

## 自测清单

- [ ] 会用 `.get(key, default)` 安全取值
- [ ] 会链式访问嵌套结构
- [ ] 列表用 `.append()`，字典用下标赋值
- [ ] 会用 `{**a, **b}` 合并字典

# 3️⃣ 网络请求（requests）

## 核心概念

**Agent 调用 LLM API 的核心工具。** GET 是"问"（获取数据），POST 是"给"（提交数据）。理解底层 HTTP，才能在出问题时 debug。

## GET vs POST 对比

| | GET | POST |
|---|---|---|
| 用途 | 获取数据 | 提交数据 |
| 参数位置 | URL 上 `?q=python` | 请求体（body）里 |
| requests 写法 | `requests.get(url, params=...)` | `requests.post(url, json=...)` |
| 典型场景 | 查天气、搜索 | 调用 LLM API |

## 语法速查（标准写法，背下来！）

```python
import requests
from requests.exceptions import Timeout, ConnectionError, HTTPError

# ---------- GET（带参数）----------
def search(query: str) -> dict | None:
    url = "https://api.duckduckgo.com/"
    params = {"q": query, "format": "json", "no_html": 1}
    resp = requests.get(url, params=params, timeout=10)
    resp.raise_for_status()          # 4xx/5xx 时抛异常
    return resp.json()

# ---------- POST（提交 JSON）----------
def call_llm(prompt: str) -> dict | None:
    url = "http://127.0.0.1:8000/post"
    headers = {"Content-Type": "application/json"}
    body = {"prompt": prompt, "model": "test"}    # json= 自动序列化
    resp = requests.post(url, json=body, headers=headers, timeout=10)
    return resp.json()

# ---------- 响应对象常用属性 ----------
resp.status_code     # 200（HTTP 状态码）
resp.text            # 响应体文本
resp.json()          # 解析为 dict/list（最常用）
resp.ok              # True 当状态码 < 400
```

## 重要认知 ⚠️（练习 3 深度理解）

1. **API 参数不是随便写的！** 参数名（`q`、`format`、`no_html`）由 **API 文档**规定，像"点菜单"——开发者的日常工作就是**先查文档，再写代码**。
2. **`json=` 参数**：`requests.post(url, json=some_dict)` 自动做三件事——字典转 JSON 字符串、设置 Content-Type 头、放入请求体。
3. **`headers` 是关键字参数**：`requests.post(url, headers, ...)` 是错的（当位置参数传给了 data），必须 `headers=headers`。
4. **永远设 `timeout`**：否则请求可能永久卡死。
5. **中文标点/多余 import**：写完检查一遍。

## 自测清单

- [ ] 能写 GET（params + timeout）和 POST（json + headers）
- [ ] 理解 params vs json 的区别
- [ ] 会用 raise_for_status()
- [ ] 参数名查 API 文档，不凭空造

# 4️⃣ JSON 数据处理

## 核心概念

API 交互的标准格式。四个函数靠一个记忆技巧区分：

```
有 s 结尾 = string（字符串）     json.dumps / json.loads
没 s      = file（文件）         json.dump / json.load
```

## 语法速查

```python
import json

data = {"name": "助手", "tools": ["search"], "enabled": True}

# ---------- 字符串转换 ----------
json_str = json.dumps(data, ensure_ascii=False, indent=2)
# → {
#     "name": "助手",
#     "tools": ["search"],
#     "enabled": true
#   }
# ensure_ascii=False: 保留中文（默认转成 \uXXXX）
# indent=2: 美化缩进

parsed = json.loads(json_str)     # JSON 字符串 → Python 对象

# ---------- 文件读写 ----------
with open("config.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)   # 写文件

with open("config.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)          # ⚠️ 读文件用 load，不是 loads！(练习4的坑)

# ---------- 类型对应 ----------
# dict ↔ object {}   list/tuple ↔ array []   str ↔ string
# int/float ↔ number  True/False ↔ true/false  None ↔ null
```

## 自定义对象序列化（练习 4 重点）⭐

`json` 不认识自定义类，要手动转成字典。**"遍历 → 转字典 → 收集 → 写入"** 是高频模式：

```python
class Message:
    def __init__(self, role: str, content: str):
        self.role = role
        self.content = content

messages = [Message("system", "你是助手"), Message("user", "你好")]

result = []                                # 1. 收集容器
for m in messages:                         # 2. 遍历
    d = {"role": m.role, "content": m.content}   # 3. 对象转字典
    result.append(d)                       # 4. 收集

with open("messages.json", "w", encoding="utf-8") as f:
    json.dump(result, f, ensure_ascii=False, indent=2)   # 5. 写入
```

> 这就是 Agent 保存对话历史的真实数据结构（system/user/assistant 三元组）。

## 常见错误 ⚠️

1. **loads/load 混淆**：`json.loads(文件对象)` 会报 TypeError，`json.loads(字符串)`、`json.load(文件对象)`。
2. **中文乱码**：忘了 `ensure_ascii=False` 会变成 `\uXXXX`。
3. **数值 0.70 → 0.7**：这是 JSON 标准行为，不用纠结。

## 自测清单

- [ ] 记住"有 s = string，没 s = file"
- [ ] 会 dumps/loads/dump/load 四个函数
- [ ] 会自定义对象转字典序列化
- [ ] 会处理 JSONDecodeError

# 5️⃣ 异常处理

## 核心概念

**代码会出错是常态，异常处理让程序"优雅失败"而不是崩溃。** 网络请求一定会失败：断网、超时、服务器 503、格式不对——不处理就会崩溃。

## 标准结构（背下来！）

```python
try:
    # 可能出错的代码
    resp = requests.get(url, timeout=10)
    resp.raise_for_status()      # 主动检查 HTTP 状态码
    return resp.json()
except Timeout:
    print("[超时] 请求超时")          # 各自处理，分别提示
except ConnectionError:
    print("[网络] 无法连接服务器")
except HTTPError as e:
    print(f"[HTTP] 状态码: {e.response.status_code}")
except ValueError:
    print("[解析] 响应不是合法 JSON")
return None                       # 兜底返回
```

## 异常类型速查表

| 异常 | 触发场景 | 处理方法 |
|------|---------|---------|
| `Timeout` | 服务器超时没响应 | 提示重试 |
| `ConnectionError` | 网络断、连不上服务器 | 提示检查网络 |
| `HTTPError` | 服务器返回 4xx/5xx | 打印状态码 |
| `ValueError` | `json()` 解析失败（非 JSON） | 提示格式错误 |
| `ZeroDivisionError` | 除零 | 提示除数错误 |
| `TypeError` | 类型不匹配（如字符串除以数字） | 提示类型错误 |
| `FileNotFoundError` | 文件不存在 | 提示路径错误 |
| `json.JSONDecodeError` | JSON 文件格式错误 | 提示格式错误 |

## 关键认知 ⚠️

1. **`raise_for_status()` 是灵魂**：它让 4xx/5xx 自动抛异常，省去手动 `if resp.status_code != 200`。没有它，503 页面会变成晦涩的 `Expecting value: line 1 column 1`。
2. **异常从特定到通用**：`except Exception` 是兜底（练习 5.1 的教训——打印 `e` 才能知道错在哪）。
3. **`except X as e`**：`e` 是异常对象，能拿到详情（如 `e.response.status_code`）。

## 自测清单

- [ ] 能背出常见异常类型及触发场景
- [ ] 会用 raise_for_status()
- [ ] 会用多个 except 分别处理
- [ ] 会打印异常详情

# 6️⃣ 类型注解（typing）

## 核心概念

类型注解**不强制运行时检查**，它的价值在于：IDE 智能提示、mypy 静态检查、代码即文档。**AI Agent 代码库几乎 100% 使用类型注解。**

## 语法速查

```python
# ---------- 基本类型 ----------
def greet(name: str) -> str:              # 参数: str，返回: str
    return f"Hello, {name}"

# ---------- 容器类型 ----------
def process(msgs: list[str]) -> dict[str, int]:   # 3.9+ 小写写法
    return {msg: len(msg) for msg in msgs}

# ---------- Optional（可能为 None）----------
from typing import Optional
def find_user(users: list[dict], uid: int) -> Optional[dict]:
    # 找到返回 dict，找不到返回 None
    ...

# Python 3.10+ 等价写法：dict | None

# ---------- Callable（函数作为参数）⭐ ----------
from typing import Callable
def execute_tool(tool_func: Callable[[str], str], input_data: str) -> str:
    return tool_func(input_data)
# Callable[[参数类型], 返回类型]
# Callable[[str], str] = 接收1个str参数、返回str的函数

# ---------- 竖线联合写法（3.10+）----------
def parse(x: str | int | None) -> str:   # 等价 Optional / Union
    ...
```

## 核心认知 ⚠️（练习 6 的最大教训）

**类型注解写"函数签名"（def 行），绝不写进函数体！**

```python
# ❌ 错误：把注解当赋值写进函数体
def execute_tool(tool_func, input_data) -> str:
    tool_func = Callable[[str], str]    # 这行是"赋值"，覆盖了真实函数！

# ✅ 正确：注解写在 def 行
def execute_tool(tool_func: Callable[[str], str], input_data: str) -> str:
    return tool_func(input_data)        # 函数体只写真实逻辑
```

**注解 = 给 IDE 看的"说明书"，描述类型；函数体 = 真正执行的代码。两者永不混淆。**

## 其他易错点 ⚠️

- `Optional[str, int]` 是**非法**的！Optional 只能包一个类型。多类型用 `Union[str, int, None]` 或 `str | int | None`。
- `config_dict: dict` 别写成 `str`（类型和实际不符，IDE 会标红）。
- `dict[]` 空方括号非法，不明确类型时写 `dict`。

## 自测清单

- [ ] 会注解参数和返回值
- [ ] 会用 list[str]、dict[str, int]
- [ ] 会用 Callable[[参数], 返回]
- [ ] 理解 Optional 只能包一个类型
- [ ] 注解只写签名，不写函数体

# 7️⃣ 面向对象基础

## 核心概念

**Agent 本身就是对象！** 用类（class）把"数据 + 行为"封装在一起。天气工具（WeatherClient）、TODO 管理器（Task/TaskManager）、工具注册表（Tool/ToolBox）都是类。

## 语法速查

```python
# ---------- 基础类 ----------
class Agent:
    def __init__(self, name: str, version: str, model: str):
        self.name = name          # self.xxx = 实例属性
        self.version = version
        self.model = model

    def __str__(self):
        return f"Agent({self.name}=v{self.version})"     # print(obj) 调用

    def __repr__(self):
        return f"Agent(name={self.name!r}, version={self.version!r}, model={self.model!r})"  # 调试调用，!r 带引号

    def greet(self) -> str:
        return f"我是 {self.name}，很高兴为您服务"        # 实例方法

agent = Agent("小助手", "1.0", "gpt-3.5")
print(agent)              # Agent(小助手=v1.0)
print(repr(agent))        # Agent(name='小助手', version='1.0', model='gpt-3.5')
print(agent.greet())      # 我是 小助手，很高兴为您服务
```

## @property（把方法变属性）⭐

```python
class Tool:
    def __init__(self, name: str, description: str, func):
        self.name = name
        self.description = description
        self.func = func

    def execute(self, input_data: str):
        return self.func(input_data)

    @property
    def is_available(self):            # property：调用时不用加括号
        return self.func is not None

tool = Tool("搜索", "查询信息", search)
print(tool.is_available)    # True（像属性一样访问，无括号！）
```

**为什么要用 @property？** 外部使用者感觉不到内部在做计算（封装）；以后逻辑变了（比如要查数据库），外部代码不用改。

## 类组合（一个类管理多个对象）⭐

```python
class ToolBox:
    def __init__(self):
        self._tools = {}               # _ 前缀 = 内部使用约定

    def register(self, tool: Tool):
        self._tools[tool.name] = tool

    def get(self, name: str) -> Tool | None:
        return self._tools.get(name)   # 不存在返回 None

    def list_tools(self) -> list[str]:
        return list(self._tools.keys())   # ⚠️ 包 list() 才是列表！

    @property
    def count(self) -> int:
        return len(self._tools)

box = ToolBox()
box.register(tool)
print(box.list_tools())   # ['搜索']
print(box.count)          # 1
```

> ToolBox 管理多个 Tool = **Agent 管理工具的真实结构**！这就是你后面做 Agent 时的骨架。

## 常见错误 ⚠️

1. **每个 .py 文件独立**：一个文件定义的类，另一个文件看不到（除非 import）。练习 7.3 的 NameError 就是因为 tool 定义在别的文件。
2. **`_tools` 不是报错原因**：下划线只是"内部约定"，`self.tools` 也能跑。
3. **`dict.keys()` 返回 dict_keys 视图**：要变列表需 `list()` 包裹。
4. **repr 惯例**：逗号后加空格、字符串带引号（`!r`）。

- [ ] 会用 @property
- [ ] 会类组合（管理多个对象）

# 🧩 贯穿性知识（练习 3 中搞懂的）

## 1. `if __name__ == "__main__":`

Python 自动给每个文件设置 `__name__` 变量：

| 使用方式 | `__name__` 的值 | 结果 |
|---------|----------------|------|
| 直接运行文件 | `"__main__"` | 执行 if 块里的测试代码 |
| 被 import | 文件名（模块名） | 跳过测试代码，只加载函数 |

```python
def search_duckduckgo(query):
    ...                       # 函数定义（给别人用）

if __name__ == "__main__":
    result = search_duckduckgo("python")   # 测试代码（自己调试用）
    print(result)
```

**作用：** 同一个文件既能"直接运行测功能"，又能"被导入复用函数"，互不干扰。

## 2. 函数参数传递

```python
def search_duckduckgo(query: str):    # query = 占位符（原材料槽）
    ...

search_duckduckgo("python")    # 传具体内容 = 放原材料
search_duckduckgo("AI")        # 传不同内容 = 换原材料
# 不传参 → TypeError: missing 1 required positional argument: 'query'
```

**函数 = 加工厂，参数 = 原材料。**

## 3. 模块化与文件名

- 文件名用**英文小写 + 下划线**（`weather_tool.py`），中文/空格/标点无法 import。
- `import` 是复用代码的基础，以后项目里用 `from 文件 import 类`。

# 🚨 常见错误清单（你踩过的所有坑，重点复习！）

| # | 错误 | 正确做法 | 出处 |
