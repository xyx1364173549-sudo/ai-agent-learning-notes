# 1️⃣1️⃣ 生成器与迭代器

## 核心概念

**`yield` 逐个产出，"产出一个暂停一次"；惰性求值——用到一个才算一个，省内存。**

LLM 的**流式响应**（streaming）本质就是生成器——API 一边吐 token，你一边接收，而不是等整段回复生成完。这是 ChatGPT 打字效果的底层原理。

## return vs yield（全部重点）

```python
def get_nums():
    return [1, 2, 3]    # return：一次性给整个列表

def get_nums():
    yield 1             # yield：产出 1，暂停
    yield 2             # 下次调用从这继续
    yield 3
```

## 语法速查

```python
# ---------- 生成器函数 ----------
def fibonacci(n: int):
    a, b = 1, 1
    for i in range(n):
        yield a                 # 逐个产出
        a, b = b, a + b         # 同时赋值（先算右边一起赋）

for num in fibonacci(8):
    print(num, end=" ")         # 1 1 2 3 5 8 13 21

# ---------- 生成器表达式（圆括号！）----------
list_compr = [x for x in range(100000)]   # 列表推导式：立即生成，占内存
gen_expr   = (x for x in range(100000))   # 生成器表达式：惰性，省内存

# 内存对比（实测）：
# 列表: 800984 字节   生成器: 200 字节（固定）！

# ---------- 记忆技巧 ----------
# 方括号 [ ] = 列表推导式（立即全部生成）
# 圆括号 ( ) = 生成器表达式（惰性，用到一个算一个）

# ---------- 模拟 LLM 流式响应 ----------
def stream_response(text: str, chunk_size: int = 3):
    for i in range(0, len(text), chunk_size):   # 步长循环
        yield text[i:i + chunk_size]            # 切片取块

for chunk in stream_response("你好呀世界", 3):
    print(f"[{chunk}]", end=" ")   # [你好呀] [世界]
```

## 关键技能：字符串切片（P2 新收获）⭐

```python
text = "你好，我是助手"
text[0:5]     # "你好，我是"（取下标 0 到 4）
text[5:10]    # 后 5 个字符
# 语法: text[开始:结束] —— 取"开始"到"结束前一位"
```

## 常见错误 ⚠️

1. **混淆列表/生成器**：`[ ]` 立即生成占内存，`( )` 惰性省内存
2. **双重循环**：取下标 + 遍历字符两回事，只需下标循环 + 切片
3. **`yield` 产出下标而非内容**：要 `text[i:i+n]` 切片，不是 `yield i`

# 1️⃣2️⃣ 装饰器

## 核心概念

**装饰器 = "给函数穿衣服"——不改原函数代码，给它增加功能。**

```python
@timer                # 等价于 slow_add = timer(slow_add)
def slow_add(a, b):   # slow_add 这个名字被"包装版"替换
    return a + b
```

**原理三步：**
1. 装饰器是**接收函数、返回新函数**的函数
2. `@timer` = 把原函数传给 timer，用返回的 wrapper **替换**原函数名
3. wrapper 内部调用原函数，前后夹带额外逻辑

## 标准模板（背下来！）

```python
from functools import wraps
import time

def timer(func):
    @wraps(func)                       # 保留原函数名/文档
    def wrapper(*args, **kwargs):      # 假装自己是原函数
        start = time.time()            # ① 进入：夹带逻辑
        result = func(*args, **kwargs) # ② 调用原函数（参数原样转交）
        end = time.time()              # ③ 退出：夹带逻辑
        print(f"耗时 {end - start:.3f} 秒")
        return result                  # ④ 返回原函数结果
    return wrapper

@timer
def slow_add(a, b):
    time.sleep(0.5)
    return a + b

slow_add(3, 4)   # 打印"耗时 0.500 秒" + 返回 7
```

## 三层结构（带参数装饰器）⭐

```python
def repeat(times: int):                    # 第 1 层：存"次数参数"
    def decorator(func):                   # 第 2 层：存"函数"（和 timer 一样）
        @wraps(func)
        def wrapper(*args, **kwargs):      # 第 3 层：真正干活
            result = None
            for i in range(times):
                result = func(*args, **kwargs)   # 用闭包记住的 times 控制循环
            return result
        return wrapper
    return decorator
```

**为什么三层？** 因为 `@repeat(3)` 要同时传"次数"和"函数"两样东西，一次函数调用只能收一批参数，所以接力传递。

**记忆口诀：**
```
第 1 层：存"参数"    → return 第 2 层
第 2 层：存"函数"    → return 第 3 层
第 3 层：干"实活"    → 用前两层的记忆执行
规律：装饰器需要存几个参数，就多几层（不带参数=2层，带1个参数=3层）
```

## 闭包（closure）——装饰器的底层机制

**内层函数可以"记住"外层函数的变量，即使外层已返回。**

```python
def repeat(times):         # times=3 存在这
    def wrapper(...):      # wrapper 能"看见"times！
        for i in range(times):   # 用到外层变量 ✅
            ...
```

## `*args, **kwargs` 参数收集器 ⭐

**规则：参数"怎么传的"决定进哪，与类型无关！**

```python
def wrapper(*args, **kwargs):
    # *args   = 收集"位置参数" → 元组 (2, 3)
    # **kwargs = 收集"关键字参数" → 字典 {'name': 'xx'}

# 调用 wrapper(2, 3)          → args=(2,3), kwargs={}
# 调用 wrapper(name="小明")    → args=(),   kwargs={'name':'小明'}

# 转交原函数：必须两个都写！
result = func(*args, **kwargs)   # 原样转交，缺一个就丢参数
```

## 常见错误 ⚠️

1. **`@wraps` 忘加**：函数名变成 wrapper，调试/日志混乱
2. **`func(*args)` 只转交位置参数**：关键字参数丢失，原函数报错
3. **`return result` 忘记**：原函数返回值丢失
4. **注解写进函数体**：类型注解只写签名（练习6的坑）

# 1️⃣3️⃣ 异步编程

## 核心概念

**异步 = 等待时让出 CPU，同时处理多个任务。** 场景：Agent 要调用 10 个工具查询，同步要 10 秒，异步可能 1 秒搞定。

**类比：**
```
同步（等菜）:  点一道菜 → 坐着等 → 吃完 → 再点下一道
异步（同时做）: 点 3 道菜 → 厨房同时做 → 哪个做好先吃哪个
```

## 4 个关键词（体系图）

| 关键词 | 作用 | 例子 |
|--------|------|------|
| `async def` | 定义协程函数（调用返回"协程对象"不执行） | `async def fetch(name):` |
| `await` | 等待协程完成（只能 await 协程！） | `r = await fetch("A")` |
| `asyncio.gather` | 并发执行多个协程 | `await gather(f1(), f2())` |
| `asyncio.run` | 启动事件循环（入口） | `asyncio.run(main())` |

## 语法速查

```python
import asyncio

async def fetch_data(name: str, delay: float) -> str:
    print(f"开始获取 {name}...")
    await asyncio.sleep(delay)      # 模拟网络延迟（让出 CPU！）
    print(f"完成获取 {name}")
    return f"{name} 的数据"

async def main():
    # 串行：约 3 秒（一个等完再下一个）
    r1 = await fetch_data("A", 1)
    r2 = await fetch_data("B", 1)
    r3 = await fetch_data("C", 1)

    # 并发：约 1 秒（同时跑！）
    results = await asyncio.gather(
        fetch_data("X", 1),
        fetch_data("Y", 1),
        fetch_data("Z", 1),
    )

asyncio.run(main())
```

**串行 vs 并发输出对比（实测观察）：**
```
串行: 开始A → 完成A → 开始B → 完成B → 开始C → 完成C
并发: 开始X → 开始Y → 开始Z → 完成X/Y/Z   ← 同时开始！
```

## 关键区分：asyncio.sleep vs time.sleep ⭐

```python
await asyncio.sleep(1)   # 异步：让出 CPU，别人可以干活 ✅
time.sleep(1)            # 同步：霸占 CPU，谁也不让，干等 ❌
```

**口诀：异步代码里永远用 `asyncio.sleep`，不用 `time.sleep`——否则异步变同步，并发失效！**

## 异步错误处理（raise 主动抛异常）

```python
async def safe_fetch(name: str, fail: bool = False) -> str | None:
    try:
        if fail:
            raise asyncio.TimeoutError   # 主动抛异常 → 跳去 except
        return f"{name} 的数据"           # 成功
    except asyncio.TimeoutError:
        print(f"[超时] {name} 获取失败")
        return None                      # 失败

r1 = await safe_fetch("正常", fail=False)   # "正常 的数据"
r2 = await safe_fetch("失败", fail=True)    # None
```

## ⭐ 异常的三个来源（重要概念！）

**异常不是只有"你写的 raise"才会发生——解释器和库内部会自动抛！**

| 来源 | 例子 | 谁抛的 |
|------|------|--------|
| ① Python 解释器 | `10/0` → ZeroDivisionError；`int("abc")` → ValueError | 解释器自动 |
| ② 第三方库内部 | `requests` 的 `raise_for_status()`、`resp.json()` | 库帮你抛 |
| ③ 你自己写 | `if fail: raise TimeoutError` | 你自己 |

**`raise_for_status()` 的真面目**——库内部就是：
```python
def raise_for_status(self):
    if 400 <= self.status_code < 600:
        raise HTTPError(...)     # ← 库帮你写了 raise！
```

**口诀：try 里可能出错（不管错从哪来）→ 程序立刻跳进匹配的 except。**

## Semaphore 并发限制（限流闸门）⭐

**类比：停车场只有 N 个车位，满了我排队等。**

```python
async def bounded_fetch(total: int, max_concurrent: int = 3) -> list:
    semaphore = asyncio.Semaphore(max_concurrent)   # 建停车场

    async def worker(i: int) -> str:
        async with semaphore:              # 占车位（满了排队）
            return await fetch_one(i)

    tasks = [worker(i) for i in range(total)]   # 列表推导式建任务
    results = await asyncio.gather(*tasks)      # 并发执行（被限流）
    return results
```

**实测效果（6 任务 × 1 秒，最多 3 并发）：**
```
不加信号量: 6 个同时跑 → 1 秒（但可能打爆 API！）
加信号量:   分 2 批跑 → 2 秒（安全，不会被限流封禁）
```

**为什么必须有它？** 真实调 OpenAI 等 LLM API 都限流，一次性发大量请求会被封禁。**Semaphore 是 Agent 并发调 API 的必备技能。**

## 何时用异步，何时用同步？

| 场景 | 用哪种 |
|------|--------|
| 调用多个 API（等待网络） | **异步** ✅ |
| 单次 API 调用、简单脚本 | 同步 |
| CPU 密集计算 | 同步/多进程（异步无效） |
| 大量文件读写 | 异步 |

**记忆：异步解决"等待"问题（IO 密集），不解决"计算"问题（CPU 密集）。**

## 常见错误 ⚠️

1. **`await` 普通函数结果**：`await greet("a")` → TypeError: 'str' object can't be awaited（只能 await 协程！）
2. **gather 传结果不传协程**：`gather(r1, r2)`（r1 是结果）→ 应 `gather(fetch(...), ...)`（传协程）
3. **用 `time.sleep` 代替 `asyncio.sleep`**：并发失效
4. **`fail == True` 当触发**：`==` 是比较不是行动！要 `if fail: raise ...`
5. **多余 import**（mytools.greet 没用上）
