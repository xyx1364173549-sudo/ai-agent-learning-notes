# 2.4 检索 + 重排序优化

## 一、总结

> **RAG 的检索是"两段式"：先用向量数据库快速粗筛（召回 top-k），再用 LLM 对候选精细排序（重排序）。这是"成本"与"精度"的平衡——向量快而粗，LLM 慢而准。**

这一步把 2.3 遗留的问题解决了：英文 embedding 模型召回不准（勾股定理排在二次方程前面），用 LLM 精排纠正回来。

---

## 二、对应知识点

### 知识点 1：两段式检索（核心方法论）

```
① 粗筛（召回 recall）：向量检索，从海量文档快速"召回" top-k 个候选
                        ↑ 快、便宜，但粗（可能召回不准）
② 精排（重排序 rerank）：对 top-k 个候选做精细排序，选出最相关的
                        ↑ 慢、贵，但准（纠正粗筛的错误）
```

**类比：招聘两轮。** HR 先粗筛简历（快，1000 份里筛出 10 份），面试官再精排（慢，从 10 份里挑 1 个录用）。

### 知识点 2：为什么非要两段？—— 成本与精度的平衡

| 方案            | 问题                                |
| ------------- | --------------------------------- |
| 只用向量检索        | 快，但不准（2.3 亲眼看到翻车）                 |
| 只用 LLM 判断全部文档 | 准，但贵且慢（1000 份全塞给 LLM，token 爆炸）    |
| **两段式**（工业标准） | 向量先筛 10 个（便宜快）→ LLM 只判断 10 个（贵但准） |

### 知识点 3：LLM 重排序（本任务的实现方式）

重排序有两种主流实现：

| 方式                            | 说明             | 本任务选择                   |
| ----------------------------- | -------------- | ----------------------- |
| **Reranker 模型**（bge-reranker） | 专门的交叉编码器模型，需下载 | ❌ 要下模型，慢                |
| **LLM 重排序**                   | 让大模型判断候选相关性    | ✅ 复用已有 DeepSeek API，无下载 |

**LLM 重排序的关键**：prompt 要明确要求"只输出编号"，这样返回值干净（如 `"2"`），方便程序后续使用。

### 知识点 4：实测证据（LLM 纠正向量粗筛）

| 阶段     | 结果                    |
| ------ | --------------------- |
| 向量粗召回  | 1. 勾股定理（错） 2. 二次方程（对） |
| LLM 精排 | 输出 **2**（二次方程）← 纠正了   |

这证明：**粗筛不准没关系，精排能把对的捞回来**。

## 三、对应代码段

```python
"""2.4 检索 + 重排序：LLM 精排纠正向量召回"""
import chromadb
from llm_client import chat          # 复用 DeepSeek 客户端

# 1. Chroma 粗召回
client = chromadb.Client()
collection = client.create_collection("study_materials")
collection.add(
    documents=[
        "二次方程的求根公式是 x = (-b ± √(b²-4ac)) / 2a",
        "Python 是一种解释型编程语言",
        "勾股定理：直角三角形两直角边平方和等于斜边平方",
    ],
    ids=["math1", "python1", "math2"],
)

# 2. 粗召回 top-2
query = "怎么解一元二次方程"
result = collection.query(query_texts=[query], n_results=2)
candidates = result["documents"][0]

print("=== 粗召回结果（英文模型，可能不准）===")
for i, c in enumerate(candidates):
    print(f"  {i+1}. {c}")

# 3. LLM 精排：让 DeepSeek 判断哪个候选最相关
prompt = f"""用户问题：{query}
候选答案：
1.{candidates[0]}
2.{candidates[1]}
请判断哪个候选答案最能回答用户问题，只输出编号（1 或 2）。
"""
reply = chat([
    {"role": "system", "content": "你是检索排序助手，只输出最相关候选的编号。"},
    {"role": "user", "content": prompt},
])
print("\n=== LLM 精排结果 ===")
print("最相关候选编号：", reply)
```

**运行结果**：

```
=== 粗召回结果（英文模型，可能不准）===
  1. 勾股定理：直角三角形两直角边平方和等于斜边平方
  2. 二次方程的求根公式是 x = (-b ± √(b²-4ac)) / 2a

=== LLM 精排结果 ===
最相关候选编号： 2
```

## 四、RAG 四步全景（阶段二前半段收官）

```
2.1 向量化（文字→向量）   → embedding，词袋模型/神经网络
2.2 切分（长文档→小块）   → chunk，重叠窗口
2.3 检索（存向量+粗召回）  → Chroma，add/query
2.4 重排序（精排）        → LLM rerank，纠正粗筛
```

这四块拼起来，就是论文第 6 章 RAG 模块的完整地基。

## 五、踩坑记录

| 编号  | 踩坑                                                                                                       | 教训                                                  |
| --- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| #64 | prompt 用 `{...}` 花括号包裹 → 变成 set，报 `Object of type set is not JSON serializable`；且 f-string 的 `f` 写进字符串内部 | 正确：`prompt = f"...{query}..."`（f 前缀在引号前，变量用 `{}` 包） |
| #65 | `query_texts=query` 少了方括号                                                                                | 应为 `query_texts=[query]`（列表）。Chroma 容错碰巧能跑，但不规范     |

**语法辨析（易混）**：

| 写法            | 是什么                             |
| ------------- | ------------------------------- |
| `"你好"`        | 字符串                             |
| `f"你好{name}"` | f-string（`f` 在引号前，`{name}` 被替换） |
| `{"a", "b"}`  | 集合（set）                         |
| `{"a": 1}`    | 字典（dict）                        |
