阶段三 · MCP 协议 · 详细版

3.1 MCP 协议（能写一个简单 MCP Server）

把 2.5b 情景记忆包成标准工具 → 任何 MCP 客户端即插即用 → Agent 工程的"标准插座"
MCP（Model Context Protocol） = 给 Agent 的"工具 + 数据"定的一套通用接口协议。我们用 MCPServer 把 2.5b 的 save_episode / search_episodes 包成两个标准工具，函数一旦被 @server.tool() 装饰，就自带"说明书"暴露到协议层——客户端先"看菜单"（list_tools）再"点单"（call_tool），不写一行对接代码。

一、痛点：你的函数很好，但"别人"没法用

没有 MCP 的世界有了 MCP 之后
函数写在项目里，只有自己能 import函数变成工具，任何 MCP 客户端即插即用
想给别的 AI 应用用？得自己写 HTTP 接口 + 文档 + 鉴权协议帮你把"接口、文档、参数校验"全标准化
每个应用一套对接方式，N 个应用 N 套代码一次实现，处处连接（Claude / Cursor / 自研应用…）

类比：没有 MCP 前，每个家电自带专属充电口，你得为每台机器配一根线；MCP 之后全行业统一成 USB-C——你写的 server 只认"MCP 这个口"，任何客户端拿标准线一插就能用。@server.tool() 就是"把自家插座改装成国标"的那一步。

二、MCP 三件套：谁是谁

┌─────────────────────────────────────────────┐
│  Host(宿主应用:Claude Desktop / Cursor / Inspector)  │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐  │
│  │ Client A │   │ Client B │   │ Client C │  │  ← 每个 server 配一个专属 Client
│  └────┬─────┘   └────┬─────┘   └────┬─────┘  │
└───────┼──────────────┼──────────────┼────────┘
        │ JSON-RPC     │              │
   ┌────▼─────┐   ┌────▼─────┐   ┌────▼─────┐
   │ Server 1 │   │ Server 2 │   │ Server 3 │   ← 轻量进程,暴露工具/资源/提示
   └──────────┘   └──────────┘   └──────────┘
角色是谁干什么
Host你正在用的 AI 应用负责 UI、模型、多 Client 管理
Client与某个 Server 一对一的连接发请求、收响应（协议对话）
Server我们的 mcp_server.py（一个进程）暴露能力：Tools / Resources / Prompts

关键关系：一个 Host 可挂多个 Server；但一个 Client 只服务一个 Server（一对一）。

三、传输通道：stdio（本阶段主角）

  • 客户端 spawn 一个 python 进程跑你的 server
  • 双方通过标准输入 / 标准输出互发 JSON-RPC 消息
  • server.run() = 启动"读 stdin → 干活 → 写 stdout"的循环

测试客户端传 command=python.exe, args=[mcp_server.py]，就是告诉系统"用哪个解释器跑哪个文件"。

你装的是 mcp 2.1.1，网上绝大多数教程停留在 1.x，API 已换代：

五、@server.tool() 把你的函数怎么了？（核心顿悟）

@server.tool()          # ① 装饰器:登记为"工具"
def add_episode(topic: str, summary: str, score: float, difficulty: str = "中") -> str:
    """记录一次学习会话。
    参数:topic 知识点, summary 会话摘要, score 练习得分(0~1), difficulty 难度。
    返回:写入成功提示,含新记录的 id。"""
    ...  # 函数体还是那个函数体,2.5b 的 save_episode 照用

装饰的那一刻发生三件事：

装饰前装饰后
函数签名 topic: str→ 工具"必填参数 topic，类型字符串"
difficulty: str = "中"→ "选填参数，默认'中'"
docstring 写给自己看→ 变成工具说明书（客户端/模型靠它决定怎么用）
函数只在模块里→ 登记进工具清单，list_tools() 能列到
一句话钉死：你写的是普通 Python 函数，@server.tool() 帮它办了"营业执照 + 菜单"——从此别人不 import 也能按菜单调用。

六、DB_PATH 为什么要钉死（工程思维）

DB_PATH = os.path.join(os.path.dirname(os.path.abspath(__file__)), "memory.db")

你的 server 是被客户端 spawn 的子进程，它的"当前工作目录" ≠ agent_project。若用相对路径 DB_PATH = "memory.db"，它会在错误的地方建库/找库——这是"Inspector 里 add 成功、query 却查不到"的头号嫌疑。__file__ = "本文件在哪"，钉死到脚本所在目录，无论谁在哪儿启动都找对库。

组件干什么

八、用代码当客户端（test_mcp_client.py 三段式）

from mcp import Client, StdioServerParameters

server_params = StdioServerParameters(command=python, args=[mcp_server.py], cwd=项目目录)

async with Client(server_params) as client:   # 2.x 一站式:spawn 进程 + 接管 stdio + JSON-RPC
    result = await client.list_tools()        # ① 看菜单
    for t in result.tools:                    #    2.x:result 是对象,要 .tools
        print(t.name)

    result = await client.call_tool("add_episode", {...})   # ② 点单
    print(result.is_error)                                 #    出错标志
    print([c.text for c in result.content])                #    真实内容在 .content[].text

    result = await client.call_tool("query_memory", {})    # ③ 读回验证

2.x 返回值套路（记死）：list_tools() → .tools；call_tool() → .content（列表，元素取 .text）+ .is_error。忘了这步会拿到"看不懂的 Pydantic 对象"。
